About Vijana BaruBaru

    


    

      
Where the code lives

      

        
          hexhoxhex/jobless_corner
          The TV app, this phone remote and the Windows app
        
        
          hexhoxhex/mkurugenzi_viewer
          Live channels, the sports schedule and the source list
            the app downloads
        
      

    


    

      
How it is built

      
    
        
  • The TV app is Kotlin with Jetpack Compose for Android TV. Video plays
          through Media3 (ExoPlayer).
    • 
        
  • Each release is a version tag (for example v0.1.297) on
          jobless_corner. GitHub Actions then builds the Android APK and the
          Windows installer and attaches both to the release. The TV checks for
          new releases and offers the update.
    • 
        
  • mkurugenzi_viewer runs on GitHub Actions on a timer: channels every 3
          hours, the sports schedule every 30 minutes, a channel health check
          every hour. It publishes JSON files (channels.json,
          schedule.json, providers.json) that the app
          downloads.
    • 
      

    


    

      
How it works

      
    
        
  • Films and series. The app looks the title up on
          TMDB, then asks the sources in order: 7Movies, MovieBox, VidNest,
          Icefy, VixSrc, 4KHDHub. The order comes from providers.json,
          so it can change without an app update. A source that fails, or never
          starts, is skipped for the next one.
    • 
        
  • Live TV. Each channel is found on its streaming site.
          A small proxy inside the app fetches the video pieces, unwraps ones that
          are disguised as images, and keeps a cushion of a few tens of seconds
          so a slow source doesn't freeze the picture. The schedule says which
          channel carries which match.
    • 
        
  • This remote. The TV runs a small web server on port
          8080, and this page talks to it over your Wi-Fi.
    • 
      

    


    

      
How to fix something

      
    
        
  1. Write down what happened and when, and send the log (App logs, then
          Send on WhatsApp).
    2. 
        
  2. Find the part that broke. Film sources: net/ (one file
          per source) and data/Repository.kt. Live TV:
          data/live/. The player: ui/PlayerScreen.kt.
          This remote: assets/remote.*. Channels and schedule:
          scraper.py in mkurugenzi_viewer.
    3. 
        
  3. Build it: Android Studio, or JDK 17 with the Android SDK, then
          ./gradlew assembleDebug. Install with
          adb install -r.
    4. 
        
  4. Test on a TV or an emulator. adb forward tcp:8080 tcp:8080
          lets you drive it with the same requests this remote sends
          (/api/state, /api/play), and
          adb logcat shows what it is doing.
    5. 
        
  5. Send the fix as a pull request.
    6. 
      

      
When a source stops working it is nearly always the
        site that changed: a new address, a renamed field, a new step to get a
        link. Compare what the site sends now with what the code expects.

    


    

      
Fixing it with an AI agent

      
    
        
  • Coding agents such as Claude Code can read the code, build it, drive a
          TV or emulator over adb and read the logs, so they can follow a problem
          from the symptom to the line that causes it.
    • 
        
  • Clone the repo, open a terminal in it, start the agent and describe
          the problem in plain words with the log file, for example:
          "Family Guy S12E5 plays in Spanish. Log attached. Find out why."
    • 
        
  • Ask it to reproduce the problem and show the cause in the log before
          it changes anything, and to change as little as it can.
    • 
        
  • Give it a way to test: an emulator, or a TV with adb over Wi-Fi, and
          the remote's requests above.
    • 
        
  • Read its changes before you build and share them. Never give it
          passwords or tokens, and keep them out of commits.
